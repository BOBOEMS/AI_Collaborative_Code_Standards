## 2. 实现自检

- [ ] **范围**：只实现当前小单元，没有顺手加入未确认功能或重构无关模块。
- [ ] **入口和结构**（`LUA-ARC-001~004`、`LUA-TASK-001`）：`main.lua` 启动顺序清楚且只有最后一个 `sys.run()`；调用方向和模块职责符合项目配置。
- [ ] **Lua 能力边界**（`LUA-LANG-001~003`、`LUA-STYLE-009`）：没有动态执行外部代码、动态 `require`、裸协程任务或依赖不稳定遍历/精度；冒号、闭包和高级特性只在语义及资源边界清楚时使用。
- [ ] **配置边界**（`LUA-ARC-005`、`LUA-PRD-001`）：板级连接、器件协议固定值和产品可调参数没有混放；业务代码不直接访问管脚或寄存器。
- [ ] **实现复杂度**（`LUA-ARC-006`）：单设备优先使用单例模块；状态模块用冒号、无状态函数用点；没有只为 PC Mock 或类型提示改变运行时结构。
- [ ] **类型和边界校验**（`LUA-TYPE-001~004`）：公开接口、`self` 和跨文件数据有准确 LuaLS 注解；`---@cast` 位于已验证分支；运行时检查集中在不可信边界。
- [ ] **接口和错误**（`LUA-API-001~005`）：有数据接口固定 `ok, data, error_code, error_context`，无数据动作固定 `ok, error_code, error_context`；code/context 职责分开，调用点处理真实失败，没有用 `assert` 或大范围 `pcall` 掩盖外部错误。
- [ ] **任务和回调**（`LUA-TASK-002~006`）：永久循环会让出执行权；回调不等待、不做长工作；等待、重试和长期资源有上限及所有者。
- [ ] **数据和资源**（`LUA-RES-001~005`）：外部数据经过适用校验；缓存、队列、字符串、文件、连接和定时器有容量或生命周期上限。
- [ ] **硬件和通信**（`LUA-PRD-002~004`、`LUA-PRD-006`）：实际 API、参数和返回语义有依据；成功判据包含设备 ID、读回值、测量值或 ACK，而不只是 `true`、长度或初始化日志；已知 BSP/API 差异已记录。
- [ ] **低功耗/存储/升级**（`LUA-PRD-005`、`LUA-PRD-007`）：涉及项已处理进入、恢复、掉电、版本、完整性和回滚中适用内容。
- [ ] **安全与日志**（`LUA-DIA-001~002`）：源码和日志不包含密钥、令牌、生产凭据或完整设备敏感身份；高频日志可控；基线代码不保留大段注释测试块。
- [ ] **打包映射**（`LUA-ARC-007`）：源码路径、`require` 名称和 LuaTools/设备端文件名一致，上传文件没有漏项。
- [ ] **来源追溯**（`LUA-SRC-001`）：非平凡 API、寄存器、协议字段、demo/旧项目和 AI 参考代码均记录来源、版本和适用边界。

## 3. 统一风格约定

以下项目属于正式约定，均需检查。带有“约”“优先”“目标”等措辞的参考值按规则完整语义判断，不机械卡数字：

- [ ] UTF-8/LF、4 空格、无 Tab，行宽约 100。
- [ ] 文件和模块名短小 ASCII；局部变量/字段为 `lower_snake_case`，常量为 `UPPER_SNAKE_CASE`，数据类型为 `UpperCamelCase`；公开驱动接口符合项目确定的 C 风格顺序。
- [ ] 名称包含必要单位，地址、寄存器、周期、阈值和重试次数使用具名常量。
- [ ] 函数和参数数量便于阅读，没有为了满足行数而过度拆分。
- [ ] 只对跨模块、需要业务判断的失败定义稳定错误码。
- [ ] 复杂流程使用具名状态；简单流程没有被强行包装成通用状态机。
- [ ] 驱动、设备、协议和非平凡业务函数有统一中文函数头，LuaLS 注解紧随其后，多步骤硬件流程有编号关键步骤注释。
