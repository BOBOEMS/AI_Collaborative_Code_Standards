# LuatOS / Lua 嵌入式产品代码规范（V1.5）

> **适用对象**：使用 LuatOS 开发嵌入式产品的个人或小团队，尤其适用于“项目负责人设计和实机验证，AI 辅助编写代码”的开发方式。
> **核心原则**：保留 C 的组织方式，保留 Lua 的表达方式，遵守 LuatOS 的调度方式。
> **目标**：代码调用链清楚、类型提示有效、接口位置固定、硬件边界明确、资源有上限、失败可恢复、结果可由目标环境复现。
> **非目标**：本规范不是 LuatOS、Lua、功能安全、网络安全或产品认证的官方合规声明。

## 1. 使用方式

### 1.1 规则等级

本版不再强制使用 R0/R1/R2、多人评审、PR 门禁或正式豁免流程。

| 等级 | 含义 |
| --- | --- |
| `MUST` | 正式约定，必须遵守规则本身。规则中写明“目标”“优先”“默认”或允许例外时，按其完整语义执行，不把参考数值机械地当作绝对门禁。无法满足时，在现有项目说明或代码旁写明原因、风险和处理方式。 |
| `PROJECT` | 由具体产品确定，例如目录名、目标模组、固件、LuaTools 版本、测试环境和发布方式。不得由 AI 按经验猜测。 |

### 1.2 AI 与项目负责人的分工

- AI 负责实现代码、解释调用链、说明缺点和风险，并提供测试入口、操作步骤、预期日志和故障判断。
- 项目负责人决定使用 LuaTools 环境还是实板测试，并负责执行调试和确认结果。
- 未获得项目负责人反馈的代码只能标记为“已编写，待验证”，不得声称功能已经通过。
- 规范不要求为生产代码搭建 PC Mock、假 I2C、假 GPIO 或依赖注入测试框架。

## 2. 工程结构与模块边界

### 2.1 推荐的传统嵌入式结构

目录按职责组织，但不要求在项目开始时创建所有空目录：

```text
USER/                   # main.lua、系统启动和产品业务
TASK/                   # 长期运行任务和任务间流程
BOARD/                  # 模组、引脚、电源、唤醒源和板级差异
DEVICE/                 # 具体器件的寄存器、命令、数据换算和状态
DRIVE/                  # GPIO、I2C、UART 等 LuatOS 外设接口封装
PROTOCOL/               # Modbus、平台协议和编解码
INCLUDE/                # 错误码、板级/产品配置和共享定义
MIDDLEWARE/             # 多模块共用且与硬件无关的功能
TEST/                   # 可选的测试入口、测试脚本或测试说明
```

项目可以使用其他目录名称。目录选择属于 `PROJECT`，判断标准是职责清楚、调用方向稳定，而不是与通用模板完全一致。

- **[LUA-ARC-001][MUST]** `main.lua` 负责 `PROJECT`、`VERSION`、模块加载、清楚可见的初始化/任务启动顺序，以及最后唯一一次 `sys.run()`。允许采用类似 `main.c` 的顺序式启动，但不得堆入寄存器细节、协议解析或永久业务循环。
- **[LUA-ARC-002][MUST]** 自研模块默认只暴露一个模块表 `M`；除 LuatOS 要求的 `PROJECT`、`VERSION` 外，变量和函数默认使用 `local`，不得把业务状态写入全局环境。
- **[LUA-ARC-003][MUST]** `require()` 普通模块不得隐式联网、开启外设、创建永久任务或启动无法停止的定时器。初始化、启动和关闭通过符合项目命名约定的显式接口完成，例如 `Device_Init()`、`App_Start()`、`Device_Close()`。
- **[LUA-ARC-004][MUST]** 调用方向保持清楚：`USER/TASK -> DEVICE/PROTOCOL -> DRIVE -> LuatOS API`。协议层不得直接操作 GPIO/UART，业务层不得直接读写传感器寄存器，`BOARD/INCLUDE` 配置模块不得反向启动业务。同层底层驱动不得只为上电/初始化顺序互相依赖；共享电源和启动次序优先由 `USER/TASK` 或明确的板级服务编排。
- **[LUA-ARC-005][MUST]** 板级配置只保存物理连接和板级事实，例如模组型号、引脚、电源、唤醒源、总线实例、总线速率和地址选择脚；器件驱动保存寄存器、命令、芯片标识、合法地址、自动递增位及固定工作模式；可由产品或平台修改的参数放入产品配置。三类配置不得混放，也不得由 AI 按常见值猜测。尚未确认的接口不导出看似可用的空配置表；应省略该项或显式标记为未启用/待确认。
- **[LUA-ARC-006][MUST]** 单板、单总线、单器件默认采用单例模块。模块函数定义和调用均统一使用点号语法；模块表保存可变状态时，`self` 作为第一个显式形参，调用处显式传入模块表（C 风格），并用 LuaLS 注解声明 `self` 类型，不使用冒号方法。无状态工具函数同样使用点语法。一个模块不得混用冒号和点号两种方式。只有确有多实例、多个会话或可替换实现需求时才引入 `new()`、句柄对象或依赖注入；不得只为 PC Mock 或类型提示改变运行时结构。
- **[LUA-ARC-007][MUST]** 必须记录“源码路径、`require` 名称、LuaTools/设备端文件名”的映射。LuaDB 扁平打包时，不得假定源码目录会保留在设备端。

## 3. Lua 语言使用边界

- **[LUA-LANG-001][MUST]** 生产代码禁止 `load`、`loadfile`、`dofile`、`loadstring`、`debug`、修改 `_G`，以及通过网络数据、配置拼接或外部输入动态执行 Lua 代码。
- **[LUA-LANG-002][MUST]** `require` 使用静态、可追踪的字符串模块名。需要异步执行时使用已核对的 LuatOS `sys` 任务、事件和定时器 API，不直接使用裸 `coroutine` 组织产品任务。
- **[LUA-LANG-003][MUST]** 不得依赖 `pairs()` 的遍历顺序、稀疏数组的 `#table` 结果、未核对的整数精度或目标固件未确认支持的 Lua 标准库能力。

### 3.1 统一代码风格约定

以下规则均为 `MUST`。其中的目标值、优先项、默认做法和明确例外保留原意：约定必须检查，但不能脱离可读性和项目事实机械执行。

- **[LUA-STYLE-001][MUST]** Lua 文件使用 UTF-8、LF、4 个空格缩进、无 Tab、无行尾空格，目标列宽约 100。为保持代码清楚可以超过目标列宽，但不得形成难以阅读的无界长行。
- **[LUA-STYLE-002][MUST]** Lua 文件名和 `require` 名称使用短小 ASCII `lower_snake_case`；现有顶层目录名和打包映射可在项目配置或代码旁说明后保留例外。
- **[LUA-STYLE-003][MUST]** 局部变量和表字段使用 `lower_snake_case`，常量使用 `UPPER_SNAKE_CASE`，LuaLS 数据类型使用 `UpperCamelCase`，模块表使用 `M`。公开驱动/设备接口统一使用 C 风格 `模块_动作_对象`（模块名_动作_对象），例如 `I2C_Read_Reg`、`LIS2DH12_Read_XYZ`、`GPIO_Set_Power_I2C`；同一模块必须保持一种命名顺序，不能在没有迁移计划时混用多套风格。依赖别名不得遮蔽常用 Lua 内建名称，例如错误码模块使用 `error_code`，不使用 `error`。
- **[LUA-STYLE-004][MUST]** 名称表达业务含义、单位和真实副作用，例如 `timeout_ms`、`voltage_mv`、`queue_limit_records`；只清软件状态的函数应命名为 `Reset_State`，不能暗示已经复位芯片。布尔量优先使用 `is_ready`、`has_network`、`enable_upload` 等肯定式名称，并包含必要主体，例如 `is_lis2dh12_inited` 优于宽泛的 `is_configured`。
- **[LUA-STYLE-005][MUST]** 地址、寄存器、周期、阈值、长度和重试上限使用具名常量；寄存器和命令可集中在 `REG`、`CMD` 或 `CONFIG` 表中。
- **[LUA-STYLE-006][MUST]** 函数以读者能够一次看懂为准。60 行和 5 个参数是触发复查的参考值，不是绝对限制；超过时应确认职责仍然单一、调用仍然清楚，也不得为了满足数字拆成大量跳转函数或配置表。
- **[LUA-STYLE-007][MUST]** 跨模块并且需要业务判断的失败使用稳定、可检索的错误码；`error_code` 表示可供程序判断的错误类别，`error_context` 表示可供日志定位的具体步骤和实际值。模块内部显而易见的失败不必层层重新包装，同一个上下文也不得在每层原样重复。
- **[LUA-STYLE-008][MUST]** 复杂流程使用 `IDLE`、`CONNECTING`、`ONLINE`、`BACKOFF`、`SLEEP_PENDING` 等具名状态；简单流程不必为了“状态机”三个字增加框架。
- **[LUA-STYLE-009][MUST]** 模块通过显式 `self` 形参消费模块状态，不使用冒号方法；闭包只用于 LuatOS API 返回句柄或短小回调等边界清楚的场景。元表、可变参数、递归和 `goto` 默认不用于产品业务；确实能降低复杂度且资源边界清楚时可以使用，但必须限制范围并能向维护者解释。
- **[LUA-STYLE-010][MUST]** 驱动、设备、协议及非平凡业务函数使用统一中文函数头，至少写明“函数名、功能说明、形参、返回值、备注”，LuaLS 注解紧随函数头。多步骤流程使用 `1.`、`2.` 等关键步骤注释。短匿名回调、简单 getter/setter 可使用一行说明；注释重点解释契约、寄存器依据、单位、时序、异常恢复和不直观原因，不逐行翻译代码。

项目可复制 [`.editorconfig`](.editorconfig) 作为编辑器提示；格式工具不能凌驾于已验证的硬件行为和代码可读性。

### 3.2 LuaLS 类型注解与运行时校验

LuaLS 注解用于补足 Lua 的静态提示，不改变 Lua 的运行时行为。注解语法以 [LuaLS 官方文档](https://luals.github.io/wiki/annotations/) 为准。

- **[LUA-TYPE-001][MUST]** 跨模块公开函数、带多个返回值的函数以及参数/返回结构不直观的内部函数，使用 `---@param` 和具名 `---@return` 描述每个位置；跨文件数据表使用 `---@class`/`---@field` 或等价明确类型，不能只写宽泛的 `table`、`any` 来消除诊断。
- **[LUA-TYPE-002][MUST]** 状态型单例可以定义 `XxxDriver` 描述 `self` 字段，跨文件结果可以定义 `XxxSample`、`XxxInfo` 等数据类型。不得只为类型检查把 `M` 改成 `M.Driver = {}` 等额外运行时层级。若把 `M` 直接声明或约束为 `XxxDriver`，必须同步声明该类型的公开方法；否则只约束各方法的 `self` 和跨文件数据结构。
- **[LUA-TYPE-003][MUST]** 可空参数和返回值使用 `?` 或显式 `|nil`。只有在成功分支、`nil` 检查、类型检查或长度检查已经证明类型后才使用 `---@cast`；注解必须覆盖全部真实返回分支，不能用错误 cast 掩盖接口缺陷。
- **[LUA-TYPE-004][MUST]** 运行时校验集中在不可信边界：板级/持久化配置进入模块、网络/串口/平台下行、LuatOS API 返回值，以及调用方不能被项目约束的公开接口。项目内部跨模块调用在入口已经验证后依赖 LuaLS 契约，不重复检查同一类型。LuaLS 注解不能替代外部输入的类型、范围和长度校验。

## 4. 接口、返回值与错误处理

- **[LUA-API-001][MUST]** 模块公开接口必须让调用方看懂用途、关键单位、参数约束、返回值和重要副作用；函数头、LuaLS 注解和实际所有返回分支必须一致。
- **[LUA-API-002][MUST]** 可能失败且返回数据的接口固定为 `ok, data, error_code, error_context`：成功返回 `true, data, nil, nil`，失败返回 `false, nil, error_code, error_context`。可能失败但不返回数据的动作固定为 `ok, error_code, error_context`：成功可只返回 `true`，失败返回 `false, error_code, error_context`。纯计算或确定不会失败的查询可以直接返回值。任何接口都不得让同一返回位置在“数据”和“错误码”之间切换；调用方不得比较 `error_context` 来选择处理分支。
- **[LUA-API-003][MUST]** 对 GPIO、I2C、UART、网络、存储等 LuatOS API，按目标模组和固件核对真实参数与返回语义，并记录关键 API 的实板结果。I2C 总线本身不规定器件的寄存器/子地址协议，不能脱离器件数据手册假定 `readReg`、`transfer` 或发送/接收组合普遍等价。官方说明、底层布尔值或返回长度不能替代数据内容校验；发现固件行为与文档不一致时写入项目技术配置和测试证据，不把临时绕行误写成所有型号通用规则。
- **[LUA-API-004][MUST]** `pcall`/`xpcall` 只放在第三方边界、可选能力或必须防止任务意外退出的顶层边界；不能用来吞掉整段业务循环的编程错误。`assert` 不用于处理外设、网络、存储或外部输入失败。
- **[LUA-API-005][MUST]** 外设、网络、等待和恢复操作必须有明确的成功、失败和最终处理。软件就绪/初始化状态只能在全部必要步骤和校验成功后置位，失败或重置路径必须清除失效状态。底层驱动默认执行一次并返回结果，重试、退避和重新初始化策略由拥有业务时限的上层统一决定；重试必须有最大次数或总时间预算，不允许零延时死循环、无限重连和递归重试。

同一个错误优先由资源所有者或业务边界记录一次完整日志，避免每层重复打印相同信息。

读取接口的调用变量也应保持返回位置可见：

```lua
local read_ok, read_data, read_error, read_context =
    device.Device_Read_Data(device)
if not read_ok then
    log.error(TAG, "device_read_failed", read_error, read_context)
    return
end
---@cast read_data DeviceSample
```

## 5. 任务、事件、回调和定时器

LuatOS Lua 任务是协作式调度。传统 C/FreeRTOS 的目录和任务职责可以沿用，但不能照搬抢占式执行假设。

- **[LUA-TASK-001][MUST]** 只有 `main.lua` 调用一次 `sys.run()`，并放在最后一条可执行语句。
- **[LUA-TASK-002][MUST]** 每个永久任务循环都必须通过已核对的 `sys.wait*`、事件等待或其他 LuatOS 机制让出执行权；禁止忙等。
- **[LUA-TASK-003][MUST]** GPIO 中断、订阅和定时器回调只做有限工作，例如保存状态、读取必要状态寄存器或发布事件，然后尽快返回；回调中不得调用等待 API。
- **[LUA-TASK-004][MUST]** 等待网络、GNSS、服务端 ACK 和跨任务事件时必须有超时，或者由明确的独立恢复机制保证不会永久失联。
- **[LUA-TASK-005][MUST]** 循环定时器、订阅、连接和长期任务必须有明确所有者，避免重复注册。功能停止、模式切换或重连时，旧资源必须停止、关闭或进入已知状态。
- **[LUA-TASK-006][MUST]** 任务间共享可变状态时必须指定唯一写者，或者通过事件传递固定字段。不得把底层 FreeRTOS 的互斥和抢占经验直接套到 Lua 协作任务上。

## 6. 数据、内存和存储

- **[LUA-RES-001][MUST]** 串口、I2C/SPI、网络、文件、KV 和平台下行数据在使用前，检查适用的类型、长度、范围、版本、字节序和校验结果。
- **[LUA-RES-002][MUST]** 接收缓存、字符串、表、离线队列、重传队列和文件处理必须有记录数、字节数或时间上限，并定义超限后的丢弃、覆盖、持久化或告警策略。
- **[LUA-RES-003][MUST]** 文件、socket、UART 会话、定时器和外设实例必须有明确所有者。打开成功后，失败、停止和模式切换路径必须关闭、复位或交还资源。
- **[LUA-RES-004][MUST]** 持久化数据必须定义键命名空间、schema 版本、默认值、写入频率和损坏/掉电恢复策略。不断增长的离线数据不得直接塞入小型 KV 配置存储。
- **[LUA-RES-005][MUST]** 不能在未知次数循环中反复用 `..` 累积大字符串，也不能周期性调用 `collectgarbage()` 掩盖内存增长。需要缓存或批量拼接时先确定上限。

## 7. 外设、网络、低功耗和升级

- **[LUA-PRD-001][MUST]** GPIO、I2C、SPI、UART、ADC 等硬件 API 只能由 `BOARD`、`DRIVE` 或项目明确指定的底层模块调用；引脚、地址、波特率和供电时序必须来自项目事实。
- **[LUA-PRD-002][MUST]** 外设初始化日志、底层 API 返回 `true` 或接收长度正确都不能单独证明设备通信和数据内容正确。驱动验证应包含只读设备 ID、关键配置回读、真实测量值或连续合理样本。对专用寄存器 API 和通用传输 API 的选择必须以器件时序、目标模组/固件文档和实板结果为依据；已知异常及绕行写入项目配置。
- **[LUA-PRD-003][MUST]** 网络注册、DNS、连接、认证、发送和业务 ACK 分别考虑失败与超时；“发送 API 返回成功”不能直接等同于服务器已接收业务数据。
- **[LUA-PRD-004][MUST]** 密钥、令牌、生产地址和设备敏感身份不得硬编码进源码或完整打印到日志。远程命令必须校验来源、长度、范围、版本、完整性和幂等性中适用项。
- **[LUA-PRD-005][MUST]** 低功耗、外设供电、唤醒源和 GPIO 保持由板级或电源管理模块集中控制。进入休眠前处理未完成任务、队列和定时器；唤醒后重新确认可能失效的网络、时间和外设状态。
- **[LUA-PRD-006][MUST]** API 没有可配置超时时，不虚构超时参数；应在任务级使用失败计数、总时间预算、外设复位、状态机或系统恢复机制兜底。
- **[LUA-PRD-007][MUST]** FOTA、脚本包和远程配置更新必须核对目标型号、版本、来源、长度、完整性和可用空间，并设计下载、校验、切换、启动确认、失败恢复和适用的回滚路径。

## 8. 日志、验证和发布

- **[LUA-DIA-001][MUST]** 模块使用稳定 TAG，产品日志优先使用 `log.*`；`print` 仅用于明确的临时板测。底层模块返回结果和上下文，由资源所有者或业务边界记录一次完整日志，避免每层重复打印。关键日志应能定位启动阶段、状态、错误原因和重试次数，高频采样日志必须可关闭、降频或仅用于测试版本。准备进入基线前，删除无效死代码和大段注释掉的临时测试代码，或将其移到 `TEST` 入口。
- **[LUA-DIA-002][MUST]** 启动日志记录脚本版本、目标板识别和可获得的固件标识，但不得原样记录 IMEI、密钥、令牌、生产服务器凭据或用户数据。
- **[LUA-VER-001][MUST]** 每个独立驱动、基础功能或业务单元都提供最小可重复验证：测试入口、烧录/操作步骤、预期日志、失败判断和恢复方法。
- **[LUA-VER-002][MUST]** 测试由项目负责人执行。AI 未看到负责人提供的日志或测量结果前，只能记录“待验证”；不得以代码存在、静态检查或历史样机日志代替本版结果。
- **[LUA-VER-003][MUST]** 本规范不要求 PC Mock。项目负责人可按需要使用 LuaTools 环境或目标板；涉及真实外设、电源、网络、低功耗和唤醒的结论最终以指定硬件和固件证据为准。
- **[LUA-VER-004][MUST]** 测试失败必须保留原始现象，不能通过删除检查、放宽判断或只截取成功日志来宣布通过。日志应包含设备 ID、测量值、ACK、状态迁移或恢复结果等有效证据。
- **[LUA-VER-005][MUST]** 发布记录至少包含脚本版本、目标模组、固件、上传文件清单、已验证功能、未验证项和已知风险。语法检查和 LuaTools 合并结果可作为辅助证据，但不等于功能通过。
- **[LUA-SRC-001][MUST]** 复制或改写厂商 demo、旧项目、第三方模块和 AI 参考代码时，记录来源和适用边界；涉及非平凡 API、寄存器和协议字段时保留可追溯依据。

## 9. 推荐代码骨架

### 9.1 传统入口

```lua
PROJECT = "PRODUCT_NAME"
VERSION = "0.0.1"

local sys = require("sys")
local app = require("app")

local TAG = "main"

local function main_task()
    log.info(TAG, "boot", PROJECT, VERSION)

    local init_ok, init_error, init_context = app.App_Init(app)
    if not init_ok then
        log.error(TAG, "app_init_failed", init_error, init_context)
        return
    end

    local start_ok, start_error, start_context = app.App_Start(app)
    if not start_ok then
        log.error(TAG, "app_start_failed", start_error, start_context)
    end
end

sys.taskInit(main_task)
sys.run()
```

### 9.2 带状态和数据类型的单例设备模块

```lua
local error_code = require("error_code")

---@class DeviceSample
---@field value integer

---@class DeviceDriver
---@field is_device_inited boolean
---@field Device_Init fun(self: DeviceDriver): boolean, integer?, string?
---@field Device_Read fun(self: DeviceDriver): boolean, DeviceSample?, integer?, string?
local M = {
    is_device_inited = false
}

----------------------------------------------------------------------------------------------------
-- 函 数 名: Device_Init
-- 功能说明: 探测并初始化设备
-- 形    参: self - 设备模块对象
-- 返 回 值: true - 初始化成功
--           false, error_code, error_context - 初始化失败
-- 备    注: 只有写入和关键配置回读均成功后才更新初始化状态
----------------------------------------------------------------------------------------------------
---@param self DeviceDriver
---@return boolean ok
---@return integer? error_code
---@return string? error_context
function M.Device_Init(self)
    -- 1. 探测设备并校验只读设备 ID。
    -- 2. 写入配置并回读关键寄存器。
    self.is_device_inited = true
    return true
end

----------------------------------------------------------------------------------------------------
-- 函 数 名: Device_Read
-- 功能说明: 读取一个设备样本
-- 形    参: self - 设备模块对象
-- 返 回 值: true, sample, nil, nil - 读取成功
--           false, nil, error_code, error_context - 读取失败
-- 备    注: 数据位置与错误位置固定，不复用第二返回值
----------------------------------------------------------------------------------------------------
---@param self DeviceDriver
---@return boolean ok
---@return DeviceSample? sample
---@return integer? error_code
---@return string? error_context
function M.Device_Read(self)
    if not self.is_device_inited then
        return false, nil, error_code.EIO, "device_not_inited"
    end

    return true, {
        value = 0
    }, nil, nil
end

return M
```

Lua 的模块表相当于一个 `.c` 文件对外公开的接口，模块内 `local` 状态相当于 C 文件中的 `static` 状态。无需为了模仿 C 再制造 `.h.lua` 文件，也无需为了约束 `DeviceDriver` 再增加 `M.DeviceDriver = {}` 这一层运行时结构。

## 10. 从 V1.0/V1.2 迁移到 V1.3

1. 保留任务让出、回调边界、资源上限、外部数据校验、板级隔离、低功耗和真实证据等可靠性规则。
2. 排版、命名、函数可读性、稳定错误码和具名状态全部保留为 `MUST`；约 100 列、60 行和 5 个参数是检查参考，不是绝对数字门禁。
3. 删除 PC Mock、假硬件接口和依赖注入的强制要求。
4. 删除 LuatOS 分册对 R0/R1/R2、多人评审、PR、正式豁免和 4 周试运行的强制依赖；C 分册和共享治理文件不受影响。
5. 目录结构改为项目选择，允许采用既有 MCU/FreeRTOS 项目的传统分层。
6. 单设备默认使用简单单例模块；对象、句柄和构造器按真实需求引入。
7. V1.0 的旧 `LUA-*` 规则编号由精简版编号替代。旧项目引用旧编号时，应按实际规则含义迁移，不能只替换字符串。
8. V1.2 项目按模块逐步统一 C 风格公开接口、点号调用方式和固定返回位置；不进行无调用方核对的全工程机械改名。
9. 在公开接口和跨文件数据结构上补齐 LuaLS 注解，把重复参数检查收敛到真实不可信边界；注解完成不等于实板验证完成。
