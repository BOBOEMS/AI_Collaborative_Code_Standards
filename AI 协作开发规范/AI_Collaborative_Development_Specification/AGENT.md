# AI 协作开发规范使用入口

更新日期：2026-10-20。

本文件说明协议架构、读取路径和使用边界。项目入口负责指向实际材料，本协议入口负责定位规则；`README.md` 用于介绍，AI 按需阅读。

## 1. 架构与规则归属

根目录维护协议规则，`example/` 是一套完整、相互关联的项目文档示例。`example/` 中的文件对应项目 `AI/` 内的同名职责，不另立通用规则。

| 正文 | 负责的规则 | 对应实例 |
|---|---|---|
| [总体方案设计规范](总体方案设计规范.md) | 目标、版本深度、功能、总体选择、验收目标，以及共用设计条件和位置 | [PROJECT.md](example/PROJECT.md)、[shared_design.md](example/shared_design.md) |
| [里程碑设计规范](里程碑设计规范.md) | 阶段划分、串行依赖、进入后的具体设计、用例及结果文件、验证节点和完成条件 | [PLAN.md](example/PLAN.md)、[M01 设计](example/milestones/M01/DESIGN.md) |
| [多 AI 会话工作流规范](多AI会话工作流规范.md) | ABCDE 权限、执行和纠错、会话组、恢复读取、配置及登记、Git 交付 | [ROLES.md](example/ROLES.md)、[SESSIONS.md](example/SESSIONS.md) |
| [文档组织与维护](文档组织与维护.md) | 文档写法、项目总目录、维护责任、状态/记录/证据、工具索引和拆分 | [项目入口](example/AGENT.md)、[状态](example/STATE.md)、[记录索引](example/records/INDEX.md) |

各业务分册在“成果文件与存放位置”处规定对应文件，文档管理引用并汇总目录。每项规则只维护一处有效正文。协议不提前展开全部实现，项目已确认技术契约及适用工程规范继续约束对应对象；冲突影响当前工作时按项目授权处理，实质调整由用户决定。

独立会话调用模块见 [session_handover_tool/](session_handover_tool/README.md)：提供 Python API、CLI 和分类原生适配器。项目配置、真实绑定和运行记录在项目及其运行目录维护；实际支持与验证限制沿工具说明读取。调用成功不代表工作交付、审核通过或自动进入下一阶段。

## 2. 项目采用与入口

项目唯一协作文档根目录记为 `AI/`，实际位置由项目 `AGENT.md` 登记。默认文件见[文档目录](文档组织与维护.md#project-layout)；已有等价文件时集中登记映射，所有会话和工作树共用，不复制各自方案与状态。

项目 `AGENT.md` 承接稳定项目约定、材料导航、采用范围、授权依据及工程入口，引用本协议，指向协作约定 `ROLES.md`、会话配置登记 `SESSIONS.md`、当前状态 `STATE.md`。入口只保留必要读取指引，文件/工具/Git 的详细协作规则沿相应正文读取，当前阶段、候选和进展只沿状态定位。不同 Agent 的原生入口通过引用接入，不能假定它们自动识别同一文件名。项目 `README.md` 仅介绍，不列为 AI 必读。

仅讨论协议、总体方案或里程碑划分时，不自动创建 ABCDE。实际进入里程碑后，按[新会话组规则](多AI会话工作流规范.md#51-每个里程碑新建会话组)建立本阶段全新 A/B/C/D/E，包括 A。尚未形成的材料说明建立时点，按当前工作需要补齐，不预建远期空表。

## 3. 按任务读取

| 当前任务 | 读取规则及项目材料 |
|---|---|
| 总体方案讨论或修订 | 总体方案设计规范、项目事实、当前 PROJECT 及必要共用设计 |
| 阶段划分或调整 | 里程碑设计规范、获批总体方案、PLAN 和实际依赖 |
| 当前阶段具体设计 | 里程碑规范第 4 章、当前任务、共用约定及待解决问题 |
| 实现、自测、用例、审核或验证 | 本角色工作流条款、当前 DESIGN/CASES、实际对象、相关工程细则及证据 |
| 文档和内部工具维护 | 文档组织规则、对应分册、实际工具索引及任务授权 |
| 会话调用或故障 | SESSIONS 指向的当前有效配置和本组绑定、已实现工具说明、授权及当前任务归属 |
| 新会话、替换或压缩恢复 | 先执行下文恢复要求，再继续相应任务 |

首次采用、角色首次执行或规则变化时，读取适用正文。正常连续工作可复用仍在当前上下文且未变化的原文，历史只按需追溯。

## 4. 新会话与上下文恢复

新会话、会话替换、上下文压缩或中断后恢复，须在继续相关动作前，重新取得项目入口、本入口和适用规则、项目协作约定、当前状态及 SESSIONS 中当前组的实际登记、当前版本边界、里程碑计划及具体设计的当前原文，再按角色补读。具体共同清单及 ABCDE 矩阵统一见[工作流恢复要求](多AI会话工作流规范.md#session-recovery)。

摘要和旧记忆只帮助定位，不能代替必需原文；已由工具完整加载的当前有效原文可直接使用。恢复先核对已有任务和资源，避免重复执行。压缩不意味着新开阶段或重建会话组；实际替换沿现有交接规则办理。

## 5. 使用时保持的边界

- [V1/V2/V3 深度](总体方案设计规范.md#2-三个版本的工作深度)分别服务当前功能、实际优化与按需研究；功能正确性问题按当前范围处理。
- [里程碑严格串行](里程碑设计规范.md#milestone-order)，每个新阶段新建五个会话，同阶段纠错和复测续用本组。
- 获批范围内连续执行，产品行为、范围、目标及实质方案变化由用户决定；问题按[分类返回](多AI会话工作流规范.md#4-问题返回修正与研究判定)处理。
- 实现、自测、审核、实物验证和整体完成分别表达；[研究结论](多AI会话工作流规范.md#research-boundary)与指标达成分别判断。
- 共用技术设计按[建立条件](总体方案设计规范.md#shared-design)放在 `AI/shared_design.md`，主题较多再分册；协作规则在 ROLES、会话配置在 SESSIONS、当前进度在 STATE，局部技术设计留在当前阶段。
- ABCDE 每批文件操作交付前提交，阶段结束正常推送，具体按[Git 交付规则](多AI会话工作流规范.md#git-delivery)；共享文件、Git 写操作及设备占用按序交接。

规则变化时更新所属正文，同步受影响实例、入口与引用；项目进度、真实会话和原始日志只在项目维护。
