# AI 协作开发规范使用入口

规范版本：V3.0。更新日期：2026-10-17。

本文件供 AI 识别协议架构、读取路径和使用边界。首次采用或相关规则变化时阅读本入口及相应分册；日常执行从项目当前状态进入，按任务补读。分册与实例导航见 [README.md](README.md)。

## 1. 协议定位与目录边界

本规范面向小团队的嵌入式产品开发，按“总体方案 → 里程碑划分 → 多 AI 会话执行”推进，围绕当前版本目标逐步设计、实现和验证。

项目采用时，在已有入口或规则中说明采用的分册、范围及可访问版本，实际方案、状态、配置和证据仍归项目唯一方案目录。规范重命名、历史归档或阅读实例，都不自动迁移既有项目，也不改变其授权和验收结果。

## 2. 协议架构与规则归属

| 文件或目录 | 维护职责 |
|---|---|
| `AGENT.md` | AI 使用入口、读取路由及跨分册边界提示 |
| [README.md](README.md) | 面向读者的总导航、规范版本和模块状态 |
| [总体方案的设计规范](总体方案的设计规范/总体方案的设计规范.md) | 产品目标、版本范围、主要能力、系统关系及总体验收目标 |
| [里程碑的划分规范](里程碑的划分规范/里程碑的划分规范.md) | 能力划分、依赖、具体设计时点、验证节点及阶段完成条件 |
| [多 AI 会话的工作流规范](多ai会话的工作流规范/多ai会话的工作流规范.md) | 角色权限、执行接续、问题返回、会话组及配置要求 |
| [文档组织与维护](文档组织与维护.md) | 项目材料的组织与维护；当前副本待修订，使用边界见第 6 节 |
| 各分册 `example/` | 可供项目采用的实例，展示对应规则，不另立通用要求 |
| `session_handover_tool/` | 后续统一调用接口及各 Agent 兼容实现，当前尚未设计实现 |

每项规则只维护一处有效正文，入口和实例通过链接引用。总体方案不提前展开全部实现细节，里程碑不另设总体目标，工作流不另立验收标准；文档管理说明材料如何维护，工具负责实现调用。

本规范约束协作方式。项目已确认的技术契约，以及适用的语言、硬件和工程规范，继续约束其对应对象。发现当前任务中的规则冲突时，指出具体条款和影响，沿项目现行授权处理；需要改变既有方案或采用范围时交用户决定，不自行拼接新旧流程。

## 3. 按任务读取规范

| 当前任务 | 需要读取的材料 |
|---|---|
| 讨论或修订总体方案 | 总体方案设计规范、项目事实及已有有效方案 |
| 划分或调整里程碑 | 已确认总体方案、里程碑划分规范和实际依赖 |
| 进入或推进当前里程碑 | 项目计划与状态、工作流规范、当前设计和获批任务 |
| 实现、自测、审核或验证 | 本角色适用规则、实际对象、用例及证据，以及直接相关设计和依赖 |
| 整理项目文档 | 项目现行组织约定；文档管理副本的待修订边界见第 6 节 |
| 调用或接入会话工具 | 项目当前有效配置、已实现工具的说明及授权；待设计模块不视为可用能力 |
| 追溯旧结论或迁移依据 | 对应历史文件和记录，不默认加载整个历史目录 |

首次采用、角色首次执行或相关规则变化时，读取对应规范正文，不能只靠实例、摘要或角色名称执行。已读且未变化的材料可以复用；日常及上下文恢复先读项目当前状态，再沿索引读取本任务所需材料，不要求每轮通读整套协议。

## 4. 项目采用与会话启动

先从现有材料明确以下信息，缺项只补当前工作所需部分：

- 项目及唯一方案入口，当前版本目标和工作深度。
- 当前里程碑、承担角色、实际工作目录及对象。
- 已确认方案、本轮允许范围、所需交付和完成条件。
- 当前结果、剩余项、最近有效记录及下一动作。

已有项目的 AI 入口应显式引用本文件及实际采用范围，不依赖不同 Agent 自动识别同一种文件名。`AGENT.md` 是协议使用入口；项目自己的入口文件名和加载方式沿所用 Agent 的实际机制设置。

仅讨论本规范、总体方案或里程碑划分时，不自动创建 ABCDE 会话。实际进入里程碑后，按[工作流会话组规则](多ai会话的工作流规范/多ai会话的工作流规范.md#51-每个里程碑新建会话组)建立本阶段会话组。尚无项目状态或完整资料时，从用户当前要求对应的设计工作开始，不以先建完整目录、表单和空白文件作为前提。

## 5. 跨分册关键约束

以下为使用提醒，具体要求以链接指向的正文为准：

- **按版本控制工作深度**：V1 完成确认功能、完整链路及必要保护、审查和实物验证；V2 围绕实际问题优化及回归；V3 按需开展深度研究。必要正确性问题随本轮处理，完整矩阵等研究不自动成为 V1 门槛。见[三个版本的工作深度](总体方案的设计规范/总体方案的设计规范.md#2-三个版本的工作深度)。
- **每个新里程碑新建 ABCDE，包括 A**：同阶段的修正、复核和复测续用本组；跨阶段通过项目文件交接，复用有效成果。见[会话连续性与交接](多ai会话的工作流规范/多ai会话的工作流规范.md#5-会话连续性与交接规则)。
- **在授权范围内连续推进**：获批方案内的实现、明确纠错和必要复测按既定接续执行；产品行为、目标、范围及实质方案调整由用户决定。见[工作流使用原则](多ai会话的工作流规范/多ai会话的工作流规范.md#1-适用与使用原则)及[问题返回规则](多ai会话的工作流规范/多ai会话的工作流规范.md#4-问题返回修正与研究判定)。
- **结论对应实际对象和证据**：实现、自测、审核、实物验证和整体验收分别记录，失败与未测保留真实状态。研究完成与工程指标达成分别判断，不为得到 PASS 自动循环修改。见[总体验收目标](总体方案的设计规范/总体方案的设计规范.md#36-总体验收目标)及[研究判定边界](多ai会话的工作流规范/多ai会话的工作流规范.md#research-boundary)。
- **未知只限制实际依赖项**：明确影响及解决时点，独立工作可以继续；后续验证须有承接。见[未决事项](总体方案的设计规范/总体方案的设计规范.md#37-未决事项)及[阶段完成与后续验证](里程碑的划分规范/里程碑的划分规范.md#7-阶段完成后续验证与版本验收)。
- **项目运行信息保持唯一来源**：当前状态、角色配置和真实会话绑定由项目维护，其他位置引用或同步；同一可变文件和设备资源按规则串行使用。见[共享资源](多ai会话的工作流规范/多ai会话的工作流规范.md#53-共享资源)及[配置与项目文件](多ai会话的工作流规范/多ai会话的工作流规范.md#6-配置项目文件与实例要求)。

## 6. 协议维护与未完成模块

模块状态统一在 [README.md](README.md) 导航。三个核心分册及其实例已编写，可按项目确认的采用范围使用。

`文档组织与维护.md` 当前为历史文件副本，尚未按现行架构修订。其旧角色权限、回报、派发和用例修正条款不作为本版新增依据；已采用现行工作流的范围以工作流正文为准，文档组织细节继续沿项目已确认约定。该副本下一轮单独设计和修订。

`session_handover_tool/` 为后续工具设计预留，方向是统一 Python 调用接口、内部兼容不同 Agent。具体命令、会话创建、回报和续派能力需在接入时验证；使用项目当前已实现的能力，不从流程箭头推断自动化已经可用。

规则变化时修改所属正文，同步受影响的实例、入口和链接；目录调整后检查引用路径。项目进度、逐轮记录、真实绑定和原始日志保留在项目材料中，本入口只维护协议使用所需内容。
