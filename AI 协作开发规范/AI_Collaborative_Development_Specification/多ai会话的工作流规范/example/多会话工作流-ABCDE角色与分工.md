# 多会话工作流：ABCDE 角色与分工（V3.0 实例）

更新日期：2026-10-17。用途：供项目采用的角色配置与执行文件。

本实例按[规范的执行文件要求](../多ai会话的工作流规范.md#project-instance)编写，通用规则以[规范正文](../多ai会话的工作流规范.md)为准。项目采用时填写实际入口和配置，调整复制后的链接，保留可访问的规范版本及确认来源。

模型表沿用[原 ABCDE 文件](../../../history_data/multi-AI-workflow/多会话工作流-ABCDE角色与分工.md)2026-10-14 的选型，仅为实例；当前可用性、原生映射和工具接入未重新核验。修改本文不改变已运行会话。

## 1. 核心约定与角色职责

每个新里程碑均新建一组 A/B/C/D/E 会话，包括新 A；同一里程碑内纠错、复核和复测续用这一组。五个角色全部建立并登记，无任务的角色待命；不得续接上一里程碑的会话来代替新组。

用户确定方案和重大取舍；本组 A 负责阶段及异常，固定接续按登记规则执行并同步 A。D/E 工作按需并行，C 保持独立审核；已确认成果通过文件引用复用，不因换组重复实现或重测。

| 角色 | 本项目采用的职责 | 边界 |
|---|---|---|
| A | 登记范围与接续，维护状态，处理阶段转换及异常，核对完成条件 | 不替用户决定方案，不改写 C 的结果 |
| B | 与用户确定当前实现及用例方案，分析方案问题并给建议 | 不自行降低目标、扩大范围或接受产品限制 |
| C | 独立审核实现、自测、用例及证据，分类并给出针对修正要求 | 默认不改生产代码，仅直接处理不影响执行及判定的机械性小修 |
| D | 实现获批生产代码，完成自测、纠错，交付候选及材料 | 不自行验收，不擅增行为、诊断接口或进入下一阶段 |
| E | 实现调试用例、脚本，执行规定验证及复测，保存原始证据 | 默认不改生产代码，不改断言迎合实现 |

## 2. Agent 与模型配置总表

阶段流程只引用角色。项目采用后明确一个维护源：尚无结构化配置时可由本表维护目标；已有执行配置时，本表从其同步，不两处手工维护。实际变更沿项目确认权限办理。

| 角色 | Agent | 模型 | 思考强度 | 备注 |
|---|---|---|---|---|
| A | Command Code CLI | `deepseek/deepseek-v4.1-flash` | `high` | 沿用原文件示例；承担轻量协调，模型及参数生效情况在接入时核对 |
| B | Codex CLI | `gpt-6.1-sol` | `xhigh` | 沿用原文件示例；项目明确实际配置与上下文要求 |
| C | Command Code CLI | `z-ai/glm-5.3-flash` | `max` | 沿用原文件示例；审核使用独立上下文，实际参数在工具接入时核对 |
| D | Antigravity | `flash`（原目标别名） | `high`（目标，原生映射待核验） | 沿用原文件主用示例；备选 Codex CLI / `gpt-6-luna` / `max`，Grok CLI / `grok-4.6` / `high`，采用前由项目确认 |
| E | DeepSeek Harness | 继承项目批准的 backend 模型 | 继承原生配置，接入时核验 | 用于用例实现与验证；实际入口及会话类型由项目接入确定 |

不同 Agent 按原生方式设置，不互套 effort、上下文或会话字段。参数未核验时如实注明；更新唯一配置源后同步展示，不以改表代替运行切换。

## 4. 同一里程碑的工作回路

本里程碑新 A 接收前组交接，建立并登记新 B/C/D/E，再核对依赖并安排新 B 与用户确认当前方案；需要 E 执行时同步确定用例目标、条件、预期、证据及停止条件。已有有效设计和审核直接引用。

```text
新 A 接收交接并建立本组新 B/C/D/E
  → 本组 B 与用户确认方案 → 本组 A 登记范围、任务和固定接续
  → D 生产实现、自测 ───────┐
  → E 用例实现、调试（按需） ─┴→ C 审核相关交付
  → 需要修正时按第 5、6 节返回
  → C 给出本轮所需审核结论
       ├─ 本阶段安排 E：C 确认可执行组合及范围 → E 验证 → C 审核证据
       └─ 本阶段无 E 验证：保留明确的后续承接
  → 本组 A 核对结束条件并移交，下一里程碑另建全新 A/B/C/D/E
```

D/E 独立部分可先交先审，分别注明实现交付、用例准备或实际验证结果。准备和离线调试不算实测通过；现成候选和用例由 C 核对既有审核仍适用后复用。

本次范围所需实现及用例均有效审核且前提具备后，C 明确候选或实现版本、用例版本及范围，才触发一次 E 验证；该确认不另增完整审核。E 核对实际组合和条件，D 不替换其正在验证的候选，新对象仅补受影响检查。

实测后修改生产代码须完成：**D 修正及自测 → C 针对审核 → E 复测受影响用例 → C 审核复测证据**。代码审核不能替代失败场景复测。

V1 围绕功能链路及必要保护；V2 围绕实际改善及回归；V3 可主要由 B/E/C 工作，本组新 D 待命，需要生产或诊断固件修改时再派任务。每个里程碑仍必须建立五个新会话，不为待命角色制造额外任务。

## 5. 移交关系速查

每项接续只保留一个触发者；同步 A 更新状态，不再次派发。工具未接入时由 A 实际安排并登记。

| 从 → 到 | 触发条件 | 交接内容 |
|---|---|---|
| 前组 A → 本里程碑新 A | 前阶段结束，按获批计划进入新里程碑 | 有效对象、结论、遗留项、承接验证、授权及资源交接 |
| 本里程碑新 A → 新 B/C/D/E | 接管后建立本阶段会话组 | 本阶段角色配置、范围、实际绑定及待命或任务安排 |
| A → B | 进入阶段，或需分析方案及原因不明的问题 | 范围、依赖、对象、需回答的问题 |
| B → 用户 | 具体方案或实质修改待确认 | 方案、依据、取舍和影响 |
| B → A | 方案已确认 | 获批版本、分工、验证和完成条件 |
| A → D/E | 启动获批任务或处理异常 | 任务、允许范围、交付和接续安排 |
| D → C，同步 A | 实现、自测或修正交付 | 对象、改动、自测、候选及缺项 |
| E → C，同步 A | 用例准备交付 | 用例、调试材料和待执行范围 |
| E → C，同步 A | 实际验证或复测交付 | 所用对象、实际结果、证据及未测项 |
| C → D，同步 A | 已批准范围内明确实现缺陷 | 依据、差异、影响和修正要求 |
| C → E，同步 A | 用例实现错误或材料缺项 | 已确认预期、具体问题；修后按需审核 |
| C → E，同步 A | 本轮组合及范围可执行验证 | 候选、用例、范围和必要条件 |
| C → A → B | 方案冲突、方法缺口或原因不明 | 事实、影响和所需分析 |
| C → A | 当前所需审核结束 | 结论、对象、限制及剩余项 |
| 本组 A → 下一里程碑新 A | 本阶段完成，按获批计划交接 | 有效成果、待承接验证、下一入口与资源停手状态；不续用本组 B/C/D/E |

报告与接续指令分别写。复用任务和轮次，注明交付类型、工作目录、获批依据、对象、结果及下一接收者。重复通知不重复派发，计划内采样和复测按相应轮次执行；晚到旧结果不覆盖当前状态，不确定回执先核对。

## 6. 问题分类与研究边界

一般返回路径按第 5 节执行：[规范问题处理规则](../多ai会话的工作流规范.md#4-问题返回修正与研究判定)为依据。实例采用以下边界：

- 明确实现差异回 D，用例实现错误回 E；证据缺项由对应作者补，不让 D 猜测修改。
- 方案、方法或验收目标的实质修改交 A→B→用户；确认后由 D/E 实施，再做针对审核及必要复测。
- C 仅直接做不影响执行和判定的机械性小修。脚本行为由 E 修正、C 审核，不自改自审；无关建议不自动成为新任务。
- 环境或输入缺失保留未完成，已有恢复办法内处理，新增资源或范围交用户决定。

研究分别记录证据有效性、指标是否达到及任务是否完成。C 审核证据，B 提方案建议，用户决定实质取舍，按[研究完成边界](../多ai会话的工作流规范.md#research-boundary)执行。

研究问题已完整回答时，可记录“研究完成、证据审核通过、指标未达到”，无新方案决定则结束，不只因否定结果增加 B 任务。依赖指标达成的工作仍受限；缺少必要条件不能算研究完成，优化任务未达标也不能改称只需测量结论。

## 7. 资源、结果与工具边界

- D 维护生产实现和自测，E 维护用例及验证材料，B 维护方案，C 维护审核，A 维护唯一当前状态；同一文件不同时写入。
- 同一板卡、串口和 SWD 同时一个执行者，D/E 明确移交；公共工程、索引和 Git 写操作串行。
- 当前正文覆盖维护，实际交付、失败和未测进入已有记录，原始材料进入证据目录，等待不制造记录。
- 单项审核或用例准备不等于阶段完成；延后验证有承接，受限收口或接受产品功能失败由用户决定。
- 交接工具下一步单独设计，方向为统一 Python 接口、内部兼容各 Agent。本实例不提供脚本或命令，不把箭头当作已自动执行。
