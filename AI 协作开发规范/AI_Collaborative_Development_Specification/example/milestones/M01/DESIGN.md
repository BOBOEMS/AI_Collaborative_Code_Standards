# M01：基础启动与本地升级恢复

规定位置：`AI/milestones/M01/DESIGN.md`。当前由 B 维护，依据为[教学范围确认](../../records/decisions/20261019-M01-scope.md)。本文件全部用于演示，术语见[总体方案](../../PROJECT.md#术语与阅读说明)，DEMO 为教学候选标识。

## 1. 目标与范围

承接 [PLAN.md 的 M01](../../PLAN.md#3-m01基础启动与本地升级恢复)：使 Boot/App 正常启动，以蓝牙来源完成请求、旧 App 备份、新镜像安装、试用确认及必要失败恢复或维修。

本阶段验证 F-01 的启动确认、F-03/F-04/F-05 及 F-07 的最小本地主机支持；完整业务交 M04，版本包交 M02，4G、URL 写入交 M03。本例不扩展实际掉电矩阵、长期压力或 Boot 自升级。

## 2. 依据和前提

采用 [shared_design.md](../../shared_design.md)的区域与保护约定。真实实施前须核实设备、匹配 Boot/App 链接镜像、备份容量、测试包及操作授权；本教学场景仅假定这些条件已在场景内确认，没有提供可操作设备参数。

FRAM 容量矛盾已记录，当前只核对事实，不进行 URL 持久化操作。实际来源见[示例边界](../../README.md#source-facts)。

## 3. 模块及关键连接

以下是教学职责划分，源码名仅说明实施范围，不代表本示例提供固件：

| 模块 / 示例源码 | 当前职责 |
|---|---|
| App 本地升级服务：`App/ota_service.c` | 本地初始化成功后确认运行；验证本地请求，完整提交后复位交 Boot |
| Boot 请求与安装：`Boot/ota_install.c` | 解释有效请求，核对镜像和恢复条件，完成备份、安装及阶段提交 |
| Boot 试用恢复：`Boot/ota_recovery.c` | 限制新 App 试用，确认后转正常启动；失败恢复或停留维修 |
| Boot 本地来源：`Boot/local_source.c` | 请求并读取目标镜像片段，检查本次数据有效，失败交统一出口 |
| 主机最小供包工具：`host/local_update.py` | 按设备请求供给对应包，保持候选、版本和长度关联 |

正常链路：健康 App 接收本地请求 → 核对目标包 → 完整提交请求并复位 → Boot 核对恢复条件 → 合格旧 App 备份 → 安装并校验新 App → 有限试用 → App 本地初始化成功后确认。

关键失败：

- 请求不完整或镜像错误：拒绝提交或安装，保持可运行对象，记录原因。
- 备份失败：不将其标为有效，不覆盖 App。
- 无合格备份的维修请求：在任何 App 擦写前拒绝，保持区内容不变。
- 试用失败：合格备份可用时恢复，否则保留可操作维修入口。
- 代表性复位中断：依据保留阶段和实体检查恢复到可操作状态；不将复位结果推广为实际掉电结论。
