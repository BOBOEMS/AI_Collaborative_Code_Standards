# M01 维修准入异常：教学事件记录

本文件集中说明一个跨实现、审核和验证的复杂事件，由 C 作为该事件维护者整理，引用 D/E 各自交付。全部内容均为教学设定，没有真实生产代码、镜像或板测；术语见[总体方案](../../PROJECT.md#术语与阅读说明)。

## 1. 为什么单独记录

初轮自测和必要审核没有识别维修入口中的擦写顺序错误，正式 T05 才暴露失败。这里保留审核遗漏、失败影响和修正范围的因果联系，便于后续分析；普通交付不要求建立 D/C/E/A 各自的过程文件。

## 2. 发现、分类与修正

场景内 R1 候选 DEMO-M01-R1 已经 C 审核，A 为 E 派发验证任务。T05 在无合格备份时发现 App 内容变化，违反[已确认设计](../../milestones/M01/DESIGN.md)的“任何擦写前拒绝”。E 停止相关操作并回报 A，A 安排 C 审核失败证据；C 判定为实现差异，由 A 派发当前 D 修正，没有通过 B 降低保护或修改预期。

D 将合格备份准入判断移到维修入口的 App 擦写前，核对相关普通安装与试用恢复入口，未改变区域、目标或用例预期。场景内开发自测覆盖无备份拒绝且不擦写、合格来源正常进入及受影响恢复路径。

D 的初轮和修正交付采用教学提交 DEMO-COMMIT-D-01、DEMO-COMMIT-D-02，当前对象 DEMO-M01-R2；这些标识不是实际 Git 对象。真实工程交付须提供自己的提交、构建和自测依据，不能由本例推断验证完成。
