# 多会话工作流：项目协作约定

更新日期：2026-10-20。规定位置：项目 `AI/ROLES.md`。本文件维护采用范围、角色边界、工作回路、交接和资源/Git 协作要求，依据为[工作流规范](../多AI会话工作流规范.md#project-instance)。

完整材料导航见 [AGENT.md](AGENT.md)，Agent/模型配置和实际会话分组见 [SESSIONS.md](SESSIONS.md)，当前阶段及进度见 [STATE.md](STATE.md)。本文件只给出这些入口，正文不重复保存配置表、原生 ID 或当前候选快照。

项目采用时明确采用范围和确认来源，填写真实工程及工具入口；通用规则引用规范，项目差异按确认权限维护。本文采用 V1/V2/V3 对应工作深度，不额外增加验收门槛。

## 术语与阅读说明

| 名称 | 本文含义与依据 |
|---|---|
| 角色与会话 | A/B/C/D/E 是职责分工，会话是承载该角色的实际对话；每个里程碑新建一组，阶段内续用 |
| Agent | 实际使用的 AI 工具，模型和思考强度按其原生方式配置，目标配置及核验状态见 SESSIONS |
| 原生会话 ID | 工具返回的真实会话标识，与角色名称、目录序号不同，实际值沿 SESSIONS 的唯一来源取得 |
| 开发自测、正式验证、审核辅助 | 分别由 D、E、C 维护相应工具，具体权限见[脚本分工](../多AI会话工作流规范.md#script-ownership) |

本文中的工具和目录名称用于配置与材料定位，不表示会话已经创建、参数已经生效或自动接续已经可用。

## 1. 核心约定与角色职责

里程碑按获批次序串行执行；每个新里程碑均新建一组 A/B/C/D/E 会话，包括新 A。同一里程碑内纠错、复核和复测续用这一组。五个角色全部建立并登记，无任务的角色待命；不得续接上一里程碑的会话来代替新组。

用户确定方案和重大取舍；本组 A 负责阶段及异常，固定接续按登记规则执行并同步 A。D/E 工作按需并行，C 保持独立审核；已确认成果通过文件引用复用，不因换组重复实现或重测。

| 角色 | 本项目采用的职责 | 边界 |
|---|---|---|
| A | 登记范围与接续，维护状态，处理阶段转换及异常，核对完成条件 | 不替用户决定方案，不改写 C 的结果 |
| B | 与用户确定当前实现及用例方案，分析方案问题并给建议 | 不自行降低目标、扩大范围或接受产品限制 |
| C | 独立审核实现、自测、正式用例及证据，维护审核辅助工具并给出针对修正要求 | 默认不改生产代码或正式用例行为，可处理不影响执行及判定的机械性小修 |
| D | 实现获批生产代码，维护开发自测及其脚本，交付修正、候选及材料 | 不自行验收，不擅增行为、诊断接口或进入下一阶段 |
| E | 维护正式用例、执行和采集脚本，完成验证及复测，保存原始证据 | 默认不改生产代码，不改断言迎合实现 |

## 2. 同一里程碑的工作回路

首个里程碑新 A 从用户确认的方案、计划和授权启动，后续新 A 接收已结束前组的交接。A 建立并登记本组新 B/C/D/E，再核对依赖并安排新 B 与用户确认当前方案；需要 E 执行时同步确定用例目标、条件、预期、证据及停止条件。已有有效设计和审核直接引用。

```text
新 A 从获批计划启动或接收已结束前组交接，建立本组新 B/C/D/E
  → 本组 B 与用户确认方案 → 本组 A 登记范围、任务和固定接续
  → D 生产实现、自测 ───────┐
  → E 用例实现、调试（按需） ─┴→ C 审核相关交付
  → 需要修正时按移交关系及问题分类返回
  → C 给出本轮所需审核结论
       ├─ 本阶段安排 E：C 确认可执行组合及范围 → E 验证 → C 审核证据
       └─ 本阶段无 E 验证：保留明确的后续承接
  → 本组 A 核对任务已结束及阶段结束条件，再移交下一组全新 A/B/C/D/E
```

D/E 独立部分可先交先审，分别注明实现交付、用例准备或实际验证结果。准备和离线调试不算实测通过；现成候选和用例由 C 核对既有审核仍适用后复用。

既有工程的接入说明随代码交付，组合审核核对模块连接和受影响业务，按[接入与集成交付规则](../多AI会话工作流规范.md#integration-delivery)执行。新验证方法或关键判定变化采用少量针对性反例，运行与部署对象保留必要关联，分别按[验证方法](../多AI会话工作流规范.md#validation-method)和[候选对象规则](../多AI会话工作流规范.md#candidate-identity)纳入现有审核。

本次范围所需实现及用例均有效审核且前提具备后，C 明确候选或实现版本、用例版本及范围，才触发一次 E 验证；该确认不另增完整审核。E 核对实际组合和条件，D 不替换其正在验证的候选，新对象仅补受影响检查。

实测后修改生产代码须完成：**D 修正及自测 → C 针对审核 → E 复测受影响用例 → C 审核复测证据**。代码审核不能替代失败场景复测；仅修正不影响执行与判定的文字、格式或资料链接时，核对受影响材料，不强制重新上板。

V1 围绕功能链路及必要保护；V2 围绕实际改善及回归；V3 可主要由 B/E/C 工作，本组新 D 待命，需要生产或诊断固件修改时再派任务。每个里程碑仍必须建立五个新会话，不为待命角色制造额外任务。

## 3. 移交关系速查

每项接续只保留一个触发者；同步 A 更新状态，不再次派发。工具未接入时由 A 实际安排并登记。

| 从 → 到 | 触发条件 | 交接内容 |
|---|---|---|
| 前组 A → 本里程碑新 A | 前阶段结束，按获批计划进入新里程碑 | 有效对象、结论、遗留项、承接验证、授权及资源交接 |
| 本里程碑新 A → 新 B/C/D/E | 接管后建立本阶段会话组 | 本阶段角色配置、范围、实际绑定及待命或任务安排 |
| A → B | 进入阶段，或需分析方案及原因不明的问题 | 范围、依赖、对象、需回答的问题 |
| B → 用户 | 具体方案或实质修改待确认 | 方案、依据、取舍和影响 |
| B → A | 方案已确认 | 获批版本、分工、验证和完成条件 |
| A → D/E | 启动获批任务或处理异常 | 任务、允许范围、交付和接续安排 |
| D → C，同步 A | 实现、自测或修正交付 | 对象、改动、自测、候选及缺项 |
| E → C，同步 A | 用例准备交付 | 用例、调试材料和待执行范围 |
| E → C，同步 A | 实际验证或复测交付 | 所用对象、实际结果、证据及未测项 |
| C → D，同步 A | 已批准范围内明确实现缺陷 | 依据、差异、影响和修正要求 |
| C → D，同步 A | 开发自测脚本或对应材料有误 | 获批预期、具体问题与受影响实现 |
| C → E，同步 A | 正式用例实现错误或材料缺项 | 已确认预期、具体问题；修后按需审核 |
| C → E，同步 A | 本轮组合及范围可执行验证 | 候选、用例、范围和必要条件 |
| C → A → B | 方案冲突、方法缺口或原因不明 | 事实、影响和所需分析 |
| C → A | 当前所需审核结束 | 结论、对象、限制及剩余项 |
| 本组 A → 下一里程碑新 A | 本阶段完成，按获批计划交接 | 有效成果、待承接验证、下一入口与资源停手状态；不续用本组 B/C/D/E |

正式交接按[五项最小内容](../多AI会话工作流规范.md#handoff-record)简述任务去向、对象、完成/检查、材料入口及剩余接续；详细说明引用已有成果和提交，不配套新建过程文件。共享原件示例见[通信归档](evidence/M01/communication/handover.txt)，只演示关键消息而非全部聊天。原生记录须可定位、持久且所需角色能访问，否则补必要内容到现有材料或一份事件记录。重复通知不重复派发，计划内采样和复测按相应轮次执行；晚到旧结果不覆盖当前状态，不确定回执先核对。

## 4. 问题分类与研究边界

一般返回路径按[移交关系](#handoff)执行：[规范问题处理规则](../多AI会话工作流规范.md#4-问题返回修正与研究判定)为依据。实例采用以下边界：

- 明确实现差异和开发自测脚本问题回 D，正式用例实现问题回 E；C 维护审核辅助工具，证据缺项由对应作者补，不让 D 猜测修改。
- 方案、方法或验收目标的实质修改交 A→B→用户；确认后由 D/E 实施，再做针对审核及必要复测。
- C 可维护自己的审核辅助工具，并处理不影响执行和判定的机械性小修；正式验证脚本行为由 E 修正、C 审核，目标和验收依据不由审核者自行改写。无关建议不自动成为新任务。
- 环境或输入缺失保留未完成，已有恢复办法内处理，新增资源或范围交用户决定。

后续里程碑发现之前成果的缺陷，由当前组按上述路径处理，不恢复旧组：实现问题交当前 D，方案问题交当前 B 并按需由用户确认；保留原证据范围，同步当前结论和依赖。

研究分别记录证据有效性、指标是否达到及任务是否完成。C 审核证据，B 提方案建议，用户决定实质取舍，按[研究完成边界](../多AI会话工作流规范.md#research-boundary)执行。

研究问题已完整回答时，可记录“研究完成、证据审核通过、指标未达到”，无新方案决定则结束，不只因否定结果增加 B 任务。依赖指标达成的工作仍受限；缺少必要条件不能算研究完成，优化任务未达标也不能改称只需测量结论。

## 5. 资源、结果与工具边界

- D 维护生产实现、开发自测及其脚本，E 维护正式用例和验证材料，B 维护方案，C 维护审核及辅助工具，A 维护唯一当前状态；同一文件不同时写入。
- 同一板卡、串口和 SWD 同时一个执行者，D/E 明确移交；公共工程、索引和 Git 写操作串行。
- 当前正文覆盖维护，普通交付沿当前成果、提交和共享消息定位，重要决定或复杂异常按事件保存；正式证据保留原始轮次和失败，等待不制造记录。
- 各会话脚本使用全英文路径并分目录保存，如 `tools/M01/C-01/`、`tools/M01/D-01/`、`tools/M01/E-01/`；沿用完整里程碑编号，能力名称写在计划和索引中，各层 INDEX.md 说明用途和入口。
- 可复制前阶段脚本到本阶段、本会话目录使用，在索引注明来源，按差异核对对象、配置和输出；原副本保留旧证据关联，未变化的有效检查可以复用，具体按[内部工具归属](../文档组织与维护.md#internal-tools)维护。
- 实测出现计划外失控或现场可能被破坏时，按[异常现场保护规则](../多AI会话工作流规范.md#test-anomaly)停止相关操作、保存证据；预期失败用例仍按既定方案处理。
- 单项审核或用例准备不等于阶段完成；延后验证有承接，受限收口或接受产品功能失败由用户决定。
- 会话调用沿[独立工具模块](../session_handover_tool/README.md)的实际支持和限制接入，持久记录是否能供所需角色读取由项目核对。本例只运行[离线材料处理工具](tools/INDEX.md)，不创建会话或上板，流程及合成回执均不证明自动接续可用。

## 6. 新会话和压缩恢复的读取入口

共同要求按[规范恢复清单](../多AI会话工作流规范.md#session-recovery)执行。先取得 [AGENT.md](AGENT.md)、[协议入口](../AGENT.md)和本文件的当前原文，再读 [STATE.md](STATE.md)的当前组及任务、[SESSIONS.md](SESSIONS.md)中该组的实际绑定和唯一配置，核对角色、目录、参数及任务归属。

继续读取 [PROJECT.md](PROJECT.md)的当前范围与约束、[PLAN.md](PLAN.md)的当前阶段条目，再沿 STATE 定位有效的 DESIGN/CASES/REVIEW/TEST_REPORT，任务依赖共用技术约定时读取 [shared_design.md](shared_design.md)。未建立的可选文件不要求读取。

| 角色 | 本项目补读内容及取得路径 |
|---|---|
| A | STATE 中未完成派工和接续、当前审核和验证结论、SESSIONS 中实际运行与停手状态，以及记录索引中的必要交接 |
| B | PROJECT 的相关选择、共用约定、当前 DESIGN/CASES 及 [records/INDEX.md](records/INDEX.md)指向的确认和方案问题 |
| C | 当前获批 DESIGN/CASES、D/E 实际交付和改动、自测材料、相关原始证据及未关闭问题，沿状态和记录索引定位 |
| D | 获批实施任务、当前设计及 C 的问题清单，真实工程的相关源码/细则由 AGENT 定位 |
| E | 当前 CASES、C 确认的候选/用例/范围、实际环境与授权、[工具索引](tools/INDEX.md)及已有结果 |

只追溯任务直接依赖的旧组和历史。摘要不能替代原文，恢复前核对已有任务和资源，首次回报简述阶段、角色、对象及下一步。是否有可执行任务以当前状态和获批依据为准，压缩不启动新阶段或重建组。

## 7. 本地提交与里程碑远程推送

按[Git 交付规则](../多AI会话工作流规范.md#git-delivery)，A/B/C/D/E 每批文件操作交付前完成必要检查并显式提交自己的文件；只读不制造提交，Git 写操作串行。报告中附实际提交，提交不代表 C 已审核或 E 已验证。

自动日志按交付批次封存，不按每条消息提交；索引在新增重要材料或入口变化时更新，STATE/SESSIONS 只更新其实际变化。

阶段结束由 A 核对全部成果及交接材料已提交，推送项目已确认远端和分支，取得成功回执后再交给下一里程碑新组。推送失败保留技术结论与本地提交，先解决同步问题，不能宣称交接完成。实际仓库、允许分支和远端沿 [AGENT.md](AGENT.md)指向的配置核对；本例仅保留填写入口，教学推送回执只演示字段，不执行真实远程操作。
