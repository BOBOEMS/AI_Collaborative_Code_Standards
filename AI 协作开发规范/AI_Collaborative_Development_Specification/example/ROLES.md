# 多会话工作流：项目协作约定

更新日期：2026-10-21。规定位置：项目 `AI/ROLES.md`。本文件只维护本项目采用的方式和实际分工，通用条款见[工作流规范](../多AI会话工作流规范.md#project-instance)。材料导航、配置和当前进度分别沿 [AGENT.md](AGENT.md)、[SESSIONS.md](SESSIONS.md)、[STATE.md](STATE.md)取得。

## 术语与阅读说明

A/B/C/D/E 表示职责，真实会话身份沿 SESSIONS 的唯一来源取得；角色名、工具目录序号和占位符不表示会话已建立。其他术语沿[规范术语表](../多AI会话工作流规范.md#术语与阅读说明)，不在此重复定义。

## 1. 本项目采用的选择

| 项目 | 本例选择 |
|---|---|
| 采用范围与深度 | 采用规范默认五角色权限及 V1/V2/V3 深度，无额外验收门槛；实际阶段授权以 AGENT 为准 |
| 会话组与派发 | 里程碑串行、新阶段全新 ABCDE、同阶段续用本组；当前组只有 A 派发，B/C/D/E 正式回报 A |
| 工程与成果汇合 | 共用同一工程工作目录，实际值只在 SESSIONS 登记；D 汇合生产成果，E 提供正式用例和验证工具，A 安排顺序 |
| 文件与设备 | 共享文件和 Git 写操作串行；同一板卡、串口、SWD 由 D/E 明确交接，读者使用的候选和相关输入保持稳定 |
| 内部工具 | 使用 [tools/INDEX.md](tools/INDEX.md)；各用途工具分目录，权限及复用沿[内部工具规则](../文档组织与维护.md#internal-tools) |
| Git 与共享材料 | 各作者提交自身交付，阶段末由 A 核对并推送；重要事件和必要原件沿现有记录、证据入口保存 |

角色权限直接采用规范中 [A](../多AI会话工作流规范.md#role-a)、[B](../多AI会话工作流规范.md#role-b)、[C](../多AI会话工作流规范.md#role-c)、[D](../多AI会话工作流规范.md#role-d)、[E](../多AI会话工作流规范.md#role-e) 的对应条款。本例没有另设角色权限；C 的技术结论独立于 A 的派发，准备、自测和正式验证分别交付。

<a id="handoff"></a>

## 2. 派发、确认和接续

本例全部采用 A 统一派发，未启用角色间直接接续。实际回路如下，技术判定沿规范[执行流程](../多AI会话工作流规范.md#3-一个里程碑的执行流程)和[问题分类](../多AI会话工作流规范.md#problem-routing)办理：

```text
A → B 确认具体方案 → A 派发 D 实现、自测及 E 用例准备
D/E → A → C 审核 → A 按 C 的分类安排修正或 E 验证
E 实际结果 → A → C 审核证据 → A 核对阶段条件、Git 和资源
```

后台 B 的待确认方案经 A 展示给用户；A 保存真实确认依据，再向本组同一 B 派发定稿或继续讨论任务。依赖该决定的实施在确认前不启动。

正式派发正文写明“执行任务：M01/d-impl01”或可直接取得的唯一快照入口；每位执行者回报自己的任务。其余交付内容及去重统一按[交接规则](../多AI会话工作流规范.md#handoff-record)，通信示例在[合成归档](evidence/M01/communication/handover.txt)，不另建编号表或逐角色过程文件。

C 确认可执行的候选、用例及范围后，A 才派发相应 E 验证；生产修正后的复核和复测按[修正边界](../多AI会话工作流规范.md#correction-retest)，不能以代码审核代替原失败场景复测。实质方案问题经 A 交 B/用户，环境不足及研究否定结果保留真实限制。

<a id="project-recovery"></a>

## 3. 启动、恢复与个别替换

启动和恢复统一执行[读取规则](../多AI会话工作流规范.md#session-recovery)，实际材料沿 [AGENT.md](AGENT.md)导航，不另维护一份恢复矩阵。

同阶段替换 A 时，本例由新 A 负责收集旧任务结果；替换执行者时，由 A 在确认旧执行停止、资源移交后派发剩余工作的新任务。详细步骤及旧任务结清按[替换接续规则](../多AI会话工作流规范.md#session-replacement)，实际停点、收集入口和余项在 STATE/已有交接中登记。

<a id="project-git"></a>

## 4. 交付提交与阶段推送

各作者按[本地提交规则](../多AI会话工作流规范.md#local-commit)提交自己的文件。阶段末由 A 核对成果汇合、有效结论、交接及停手状态，按[远程同步规则](../多AI会话工作流规范.md#milestone-push)推送 AGENT 所指配置中的目标，取得成功回执；失败则保留技术结论并处理同步问题。教学回执不代表实际执行。

下一阶段仅在结束条件、同步和授权均具备时交接全新组；本例计划不自行赋予后续阶段启动权限。
