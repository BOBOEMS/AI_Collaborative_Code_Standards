## 1. 协议定位与采用

本协议用于多个 AI 会话协作完成软件实现、审核和测试。A/B/C/D/E 是角色槽，角色总表维护默认 Agent、模型和思考要求；根目录命令表维护角色操作，Agent 详情维护工具设置方法。

用户最新明确指示优先。项目采用本协议时，由用户确定总体方案、里程碑、执行范围和角色授权；技术契约、设备操作及 Git 授权沿项目当前生效入口。A 只在已授权范围内调度，B 产出的所有方案由用户拍板。

本目录维护通用规则、角色与工具手册。项目的阶段状态、候选身份、逐轮报告、审核和原始证据保存在项目自己的方案目录；每个项目只维护一个有效方案入口，所有会话与工作树引用同一处。

## 3. 读取与接入

1. 首次采用或规则变化时，读本入口、角色分工及文档组织与维护；需要调用工具时再读唤醒手册对应小节。
2. 用户确定项目范围、里程碑及角色授权后，指定项目唯一方案目录、当前状态文件和会话登记入口，复用已有文件。
3. 项目的 `AGENTS.md` 或既有 AI 入口链接本协议，并指向该项目的规则、计划、状态和任务卡。具体项目接入在其获批安排下执行。
4. 日常从项目当前状态定位任务，再读对应有效方案、用例和最近有效记录；未变化且已读的规则可复用。

Reuse_RTU 已讨论从 H2 切换的方向；具体迁移、会话绑定和项目入口调整按后续获批安排及项目当前入口执行。本轮只整理协议目录，不启动板测或跨会话调度。

## 4. 维护方式

规则变化时修改对应唯一正文，并更新必要指针。角色操作调整归命令表，工具参数机制归 Agent 详情，项目执行事实归项目记录。文件过长时按主题拆分并更新本索引，保留历史证据的原覆盖范围。

## 现有实现参考与边界

已只读参考 Reuse_RTU 的 Python 统一入口、配置模块与原生适配器。其当前接口只支持 C/D，A/B/E 和 Command Code/Grok 适配仍待接入。本协议不会把示例命令当作已实现全部角色，也不修改其项目配置或运行绑定。详细映射与调用示例只维护在 [命令表](命令表.md)。
