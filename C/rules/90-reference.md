## 附录 B：规范来源与使用边界

- **BARR-C:2018**：作为嵌入式 C 实践依据，仅在团队内部查阅已下载的受版权保护 PDF。本规范用团队语言重新表达适用规则，不复制或对外再发布全文，也不声称通过 BARR-C 认证。
- **Zephyr Coding Guidelines / Style**：参考其工程约束、错误处理、并发边界、追溯和自动检查思路；本团队规则及项目执行配置是最终可执行依据。
- **OpenTitan C/C++ Style Guide / `.clang-format`**：仅作为格式选项和自动化实现参考。其默认风格（包括缩进选择）不直接成为团队规则，团队 `.clang-format` 应显式覆盖为本规范要求。
- C 语言边界、FreeRTOS 无限事件等待及 PowerShell 编码的公开依据与团队裁决见 [规则来源矩阵](../rule_source_matrix.md) 的补充依据；不将某个工具链或内核的实现细节升级为所有项目的规则。
- **[SRC-003][REVIEW-BLOCK]** 复制或修改上游配置文件时，必须保留适用的许可证与归属说明；依据文件的来源、版本和哈希见 `../规范依据/C/SOURCES.md`。

## 附录 C：项目执行配置最小清单

使用 [共享项目基线模板](../../共享/项目基线模板.md) 和 [C 技术配置模板](../project_profile_template.md) 核对字段；已有 `PROJECT.md`、专项文档或机器配置时只补缺项，缺少承载位置时才新建文件。协作方式及真实确认来源只维护在项目基线，技术事实与验证快照分开记录。以下内容按项目适用范围保留：

1. 权威工具链、版本、构建命令和支持的硬件变体；
2. IRQ 优先级表及 `configMAX_SYSCALL_INTERRUPT_PRIORITY` 对照；
3. 每任务栈、MSP、heap、Flash 和 RAM 预算/阈值；
4. NVM 分区与格式版本、OTA 分区与回滚策略；
5. 实际责任人、适用专项测试和发布清单位置；多人团队还须记录模块主负责人/备份；
6. 项目权威 `error.h` 路径、有符号状态类型、外部错误码隔离及适配边界，以及完整使用或按职责裁剪错误码目录的选择；裁剪版必须保持文件引用方式以及保留项的符号、数值、别名和语义不变。
7. 已采用的实现定义行为及工具链依据、事件任务无限等待的适用条件、DMA 取消后归还缓冲区的判据，以及 Boot/应用启动交接契约。

- **[SRC-004][REVIEW-BLOCK]** 规则来源、团队调整、检查方式和许可证边界统一维护在 `rule_source_matrix.md`；权威分片的规则 ID 变更时必须同步更新该矩阵。
