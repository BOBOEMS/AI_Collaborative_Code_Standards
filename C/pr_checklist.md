# C 技术检查索引

> 适用于 C 改动的自检与集中复审。只核对本次适用门禁，结果写入现有里程碑、PR 或等价记录；本文件不额外启动审查轮次。`不适用`须有依据，同组项目可以合并说明；未执行的适用项记为“未验证”。
>
> 通过 [C 读取入口](AGENTS.md) 定位本次适用的权威规则；无需因核对本表再读合订版。协作方式与团队人数的适用边界见 [共享基线](../共享/团队治理与评审基线.md)，豁免或紧急修复见 [共享流程](../共享/豁免与紧急修复流程.md)。

## 1. 共用记录入口

| 项目 | 内容 |
| --- | --- |
| 本次变更及检查记录 | 引用里程碑、PR 或现有工作记录 |
| 源码、配置与检查范围 | 引用本次实际版本、文件/函数及检查覆盖 |
| 风险或技术影响 | 个人+AI 引用已有说明；团队记录 R0/R1/R2 及理由 |
| 适用门禁、检查结果与证据 | 引用实际记录；同一结果不再抄写 |
| 豁免及批准记录 | 适用时引用；角色与人数按已采用流程 |

已有记录覆盖这些字段时只保留入口，无需重新填写一张表。一次结果可同时支持设计一致性、C 规范和功能核查，但三类结论分别记录，不能互相替代。

## 2. 适用方式与技术风险

协作方式引用项目基线，不在本表重新选择。C 高风险范围见 [基础规则第 1.1 节](rules/00-core.md)，技术证据和记录要求见 [构建与评审规则第 16 节](rules/50-build-review.md)。下列 R0/R1/R2 引用表示相应技术验证门槛；个人+AI 不另填 R 标签，仍须按实际变化满足适用要求。团队模式保留共享基线的非作者人数与批准要求。

## 3. C 技术门禁（19 项）

- [ ] **GATE-01 范围**：改动只覆盖声明的需求/缺陷，无无关重排、生成物或第三方代码误改。
- [ ] **GATE-02 规则**：新增/修改代码符合团队规范；例外已关联有效豁免。
- [ ] **GATE-03 格式**：本次改动通过团队固定版本的格式检查。
- [ ] **GATE-04 构建**：风险等级要求的所有配置均完成 clean build，命令、工具链和日志可追溯。
- [ ] **GATE-05 警告**：没有新增编译/链接警告；历史警告与批准基线一致。
- [ ] **GATE-06 测试**：已按 R0/R1/R2 提供验证证据，正常、边界和失败路径覆盖与风险匹配。
- [ ] **GATE-07 接口**：团队函数符合 `Module[_Feature]_VerbObject`；结构体/联合体、枚举类型及枚举值符合 `NAM-009`；容量与有效长度、单位、所有权、线程/ISR 上下文和返回值语义明确；固定容量省略长度时有验证依据；自研头文件可独立包含，固定签名例外有依据。
- [ ] **GATE-08 错误处理**：状态接口仅以 `0` 表示成功、以负数符号表示失败，正数未用于状态返回；有业务意义的返回值已处理；`error.h` 裁剪只删除未使用项，文件引用方式及保留项的符号、数值、别名和语义不变，且未将宏改写为枚举；若声称裁剪降低 Flash，已在同一工具链和优化选项下提供 MAP/BIN 对比及被移除的段或符号；项目私有负值目录与外部同名宏已按 API-008 隔离，实际包含链和最终宏值已检查；超时、重试、降级、日志或恢复策略明确。
- [ ] **GATE-09 数值安全**：有符号/无符号、窄化、溢出、移位、除零、有符号除法/取余不可表示边界、字节序和单位转换已核对；实现定义行为有目标/工具链依据及封装和验证记录。
- [ ] **GATE-10 内存安全**：指针、数组、缓冲区长度、生命周期、对齐及重叠访问已核对；字符串终止和截断已处理；无未豁免的 VLA/alloca，允许项计入最坏栈预算。
- [ ] **GATE-11 并发**：共享数据、临界区、锁顺序、可重入性、优先级反转和竞态已核对。
- [ ] **GATE-12 ISR/DMA**：无阻塞操作；FreeRTOS API、逻辑优先级与 NVIC 编码合法；DMA 完成/错误/取消及迟到通知处理明确，确认硬件停止访问后才归还缓冲区，缓存策略正确。
- [ ] **GATE-13 时间**：tick 回绕、总超时预算、计时单位及 RTC/系统时间转换正确；无限事件等待满足适用条件；一次操作的重试有次数或总时间上界及耗尽动作，长期重连有独立状态和退出条件。
- [ ] **GATE-14 协议/存储**：未直接依赖结构体布局；版本、长度、字节序、校验及掉电一致性已处理。
- [ ] **GATE-15 资源预算**：Flash、RAM、Heap、MSP 和任务栈未超项目阈值，或已有有效豁免。
- [ ] **GATE-16 可观测性**：关键失败保留足够日志/错误码，且日志不泄密、不阻塞关键实时路径。
- [ ] **GATE-17 R2 专项**：目标型号、地址范围、完整性、故障恢复和回滚路径已验证；涉及 Boot 时，入口/栈/向量表、中断及 DMA 等启动交接契约已有对应目标板证据；不适用项有说明。
- [ ] **GATE-18 可维护性**：项目配置、IRQ 表、模块责任表、测试/发布说明等受影响文档已同步。
- [ ] **GATE-19 注释与编码**：新增自研 `.c/.h` 文件为 UTF-8（无 BOM）且具有中文文件职责说明；新增或修改的函数、结构体/联合体、枚举和宏已按适用字段补齐中文注释；硬件地址、容量、时钟、超时及协议常量的依据可追踪；块注释、TODO 和注释掉代码符合 `DOC-001~010`。

规模提醒按 `REV-006` 在已有检查点评估，不重复启动审查。生成代码、上游代码和机械格式化必须与逻辑改动分开提交。

## 4. 结果与后续处理

- 通过项简记范围、结果与证据；发现问题时说明位置、规则或设计依据、影响及处理，不输出重复长报告。
- 结果、源码、配置和相关依赖仍适用时直接复用；修正后只复核受影响项。审查结束条件按已采用流程执行，待验证项不写成通过。
- 团队模式从引用记录核验所需评审者、非作者身份、结论、日期及合并批准；个人+AI 保留其协作规范要求的用户确认和必要独立复审记录。
- 构建、功能测试或格式检查通过只能支持各自覆盖的结论，不能把勾选门禁当成已执行检查。
